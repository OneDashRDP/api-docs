# OneDash API

Базовый URL: `https://api.rdp-onedash.ru/api`

Все примеры идентификаторов, адресов и ключей в документе вымышлены.

## Общие правила

- Используйте HTTPS.
- Для POST-запросов передавайте JSON с заголовком `Content-Type: application/json`.
- Ответ всегда возвращается в JSON.
- Успешный ответ содержит `"type": true`.
- Ошибка содержит `"type": false`, поле `err` и, как правило, пояснение `message`.
- Проверяйте и HTTP-код, и поле `type`.
- Не записывайте API-ключи и пароли VPS в логи.

## Авторизация

Все методы `/api/*`, кроме `GET /api/ping`, требуют API-ключ:

```http
Authorization: Bearer YOUR_API_KEY
Accept: application/json
```

Пример:

```bash
curl -sS \
  -H 'Accept: application/json' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  'https://api.rdp-onedash.ru/api/balance'
```

API-ключ создаётся и управляется в личном кабинете. Если для ключа настроен IP whitelist, запросы принимаются только с разрешённых адресов.

Для операций повышенного риска непустой IP whitelist обязателен. Это относится к созданию и клонированию VPS, получению реквизитов доступа, смене пароля, продлению, смене тарифа, переустановке и удалению VPS. Также whitelist требуется для операций со снимками и резервными копиями, смены IP, локации и процессора, покупки дополнительных опций.

## Формат ответов

Успешный ответ:

```json
{
  "type": true,
  "data": {}
}
```

Ответ с ошибкой:

```json
{
  "type": false,
  "err": "wrong_parameters",
  "message": "Invalid request parameters"
}
```

Основные HTTP-коды:

| Код | Значение |
|---:|---|
| `200` | Запрос выполнен |
| `202` | Операция принята и выполняется асинхронно |
| `401` | API-ключ отсутствует, недействителен или отключён |
| `403` | Доступ с текущего IP запрещён либо требуется IP whitelist |
| `404` | Объект или метод не найден |
| `409` | Конфликт состояния или другая операция уже выполняется |
| `415` | Для метода требуется JSON-тело |
| `422` | Некорректные параметры либо отсутствует подтверждение |
| `429` | Превышен лимит запросов; учитывайте заголовок `Retry-After` |
| `500` / `503` | Временная ошибка сервиса |

Повторяйте только безопасные запросы. Для POST-операций сначала проверьте результат предыдущего запроса, чтобы не создать дубликат.

## IP whitelist и подтверждение операций

Для чувствительных операций:

1. Настройте для API-ключа хотя бы один разрешённый IP в личном кабинете.
2. Отправляйте запрос с этого IP.
3. Если метод предусматривает подтверждение, передайте `"confirm": true`.

Отсутствие подтверждения возвращает ошибку `confirmation_required`.

## Повторные запросы

Для создания, отката и удаления снимков, синхронизации, восстановления и удаления резервных копий, смены IP, локации, процессора и покупки дополнительных опций требуются IP whitelist, `"confirm": true` и заголовок `Idempotency-Key`.

```http
Idempotency-Key: 71a6850d-5600-4b18-b184-c447eeac8f31
```

Используйте отдельный ключ для каждой операции. Длина ключа — от 16 до 128 символов; разрешены латинские буквы, цифры, `.`, `_`, `:`, `-`.

Повтор с тем же ключом, методом, ID и параметрами возвращает сохранённый ответ без повторного выполнения. Заголовок `Idempotency-Replayed: true` означает, что ответ получен из журнала. Ключ действует в пределах аккаунта, включая разные API-ключи. Автоматического срока истечения у него нет.

Если параметры изменились, возвращается HTTP `409` и `idempotency_conflict`. Если предыдущий запрос ещё выполняется, возвращается `operation_in_progress`. Дождитесь его результата и повторите запрос с прежним ключом.

При `operation_outcome_unknown`, потере соединения или таймауте не создавайте новый ключ для той же операции. Проверьте состояние VPS или заказа; при необходимости обратитесь в поддержку. Неопределённый результат не запускается повторно автоматически.

Для перечисленных методов передавайте параметры только в JSON-теле. Значения `confirm`, `include_ram`, `allow_data_loss` и флаги дополнительных опций должны быть JSON boolean, например `true`, а не строкой `"true"` или числом `1`. Неизвестные параметры и `null` не принимаются. Некорректные параметры возвращают HTTP `422`, другой формат тела — HTTP `415`.

Для этих POST-методов действует лимит 20 запросов в минуту на API-ключ и метод, включая повторы. Для новых методов чтения — 60 запросов в минуту; для истории покупок — 6. При превышении возвращается HTTP `429` с `Retry-After`.

Платные изменения возвращают `status=payment_required` и ссылку `payment_url`. Завершите оплату по ссылке. Создание ссылки не означает, что изменение уже выполнено, и не списывает средства с баланса автоматически. Ответ HTTP `202` со `status=accepted` означает принятие операции; проверяйте результат через информацию о VPS или заказе.

## Авторизация и справочники

### GET /api/auth/check

Проверяет API-ключ и доступ текущего IP.

```json
{
  "type": true,
  "data": {
    "authorized": true,
    "client_ip": "203.0.113.10"
  }
}
```

### GET /api/locations

Возвращает доступные локации и типы процессоров.

```json
{
  "type": true,
  "data": {
    "locations": [
      {
        "location": "msk",
        "processors": ["intel", "amd"]
      }
    ],
    "synced_at": 1893456000
  }
}
```

Перед созданием VPS используйте только сочетания `location` и `processor`, присутствующие в этом ответе.

### GET /api/systems

Возвращает доступные операционные системы.

```json
{
  "type": true,
  "data": [
    {"code": "ubuntu_22", "name": "Ubuntu 22"},
    {"code": "windows_2022_en", "name": "Windows Server 2022 EN"}
  ]
}
```

В запросах создания и переустановки передавайте значение `code`.

### GET /api/tariffs

Возвращает тарифы для выбранной локации и процессора.

Query-параметры:

| Параметр | Обязательный | Описание |
|---|---:|---|
| `location` | нет | Код локации; по умолчанию `msk` |
| `processor` | нет | Тип процессора; по умолчанию `intel` |

Пример:

```http
GET /api/tariffs?location=msk&processor=intel
```

```json
{
  "type": true,
  "data": {
    "location": "msk",
    "processor": "intel",
    "currency": "RUB",
    "items": [
      {
        "id": 5,
        "name": "First",
        "config": {"cpu": 1, "ram": 1, "hard": 100},
        "prices": [
          {"period": 7, "price": 49, "discount": 0}
        ]
      }
    ]
  }
}
```

## Баланс

### GET /api/balance

Возвращает баланс аккаунта.

```json
{
  "type": true,
  "data": {
    "balance": 100,
    "currency": "RUB",
    "locale": "ru"
  }
}
```

### POST /api/balance/top-up

Создаёт ссылку для ручного пополнения баланса.

Параметры:

| Параметр | Тип | Описание |
|---|---|---|
| `amount` | number | Сумма от `1` до `1000000` |

```json
{
  "amount": 500
}
```

```json
{
  "type": true,
  "url": "https://pay.example.com/payment/EXAMPLE"
}
```

Баланс изменится только после успешной оплаты по полученной ссылке.

### GET /api/balance/transactions

Возвращает последние 50 движений баланса текущего аккаунта. Параметры не требуются.

```json
{
  "type": true,
  "data": {
    "items": [
      {
        "created_at": 1893456000,
        "direction": "plus",
        "amount": "100.00",
        "currency": "RUB",
        "info": "Пополнение баланса"
      }
    ],
    "limit": 50
  }
}
```

`created_at` — Unix timestamp в секундах. `amount` — сумма строкой без символа валюты. `direction` сохраняет значение журнала кабинета. Метод возвращает движения баланса; историю оформления заказов запрашивайте отдельно.

## Заказы

### GET /api/orders

Возвращает список заказов текущего аккаунта.

```json
{
  "type": true,
  "data": [
    {
      "order_id": 10001,
      "tariff": {"id": 5, "name": "First"},
      "location": "msk",
      "vps_list": [],
      "finish_time": {"epoch": 1893456000, "days_remaining": 30}
    }
  ]
}
```

### POST /api/orders/info

Возвращает информацию об одном заказе.

```json
{
  "order_id": 10001
}
```

```json
{
  "type": true,
  "data": {
    "order_id": 10001,
    "tariff": {"id": 5, "name": "First"},
    "location": "msk",
    "vps_list": [],
    "finish_time": {"epoch": 1893456000, "days_remaining": 30}
  }
}
```

### POST /api/orders/renew

Продлевает заказ с оплатой с баланса аккаунта. Требуются IP whitelist и `confirm=true`.

| Параметр | Тип | Описание |
|---|---|---|
| `order_id` | integer | ID активного заказа |
| `period` | integer | Период продления в днях |
| `confirm` | boolean | Должен быть `true` |

```json
{
  "order_id": 10001,
  "period": 30,
  "confirm": true
}
```

```json
{
  "type": true,
  "order_id": 10002
}
```

Этот метод выполняет разовое продление. Управление автопродлением доступно только вручную в личном кабинете и через API не предоставляется.

### POST /api/orders/{id}/tariff

Меняет тариф активного заказа. Требуются IP whitelist и `confirm=true`.

```json
{
  "tariff_id": 6,
  "confirm": true
}
```

Успешный запрос возвращает HTTP `202`:

```json
{
  "type": true,
  "data": {
    "order_id": 10001,
    "old_tariff_id": 5,
    "new_tariff_id": 6,
    "new_tariff_name": "Second",
    "remaining_value_preserved": true,
    "lease_period_recalculated": true,
    "status": "changing"
  }
}
```

После завершения повторно запросите информацию о заказе.

### GET /api/orders/history

Возвращает историю покупок текущего аккаунта: заказы, дополнительные опции, смену IP, локации и процессора. В истории могут быть неоплаченные покупки.

Query-параметры:

| Параметр | По умолчанию | Ограничение |
|---|---|---|
| `from` | 29 дней до `to` | Дата `YYYY-MM-DD` |
| `to` | Текущая дата | Дата `YYYY-MM-DD`, не позже текущей |
| `page` | `1` | От `1` до `1000000` |
| `per_page` | `50` | От `1` до `100` |

Даты включаются в диапазон и рассчитываются по времени Москвы. Максимальный диапазон — 31 календарный день. Для большего периода отправьте несколько запросов.

```json
{
  "type": true,
  "data": {
    "items": [
      {
        "id": "order_10001",
        "title": "Покупка VPS",
        "status": "success",
        "status_text": "Успешно",
        "amount": "300.00",
        "currency": "RUB",
        "created_at": 1893456000,
        "info": []
      }
    ],
    "pagination": {
      "total": 1,
      "per_page": 50,
      "current_page": 1,
      "last_page": 1,
      "from": 1893445200,
      "to": 1896037199
    }
  }
}
```

`pagination.from` и `pagination.to` — границы запрошенного периода в Unix timestamp, а не номера строк. Если `page` превышает число страниц, кабинет возвращает последнюю страницу.

`status=success` соответствует успешной покупке, `status=fail` — покупке без подтверждённой оплаты. `info` содержит дополнительные сведения без HTML. Ссылки повторной покупки из кабинета не возвращаются.

### POST /api/orders/{id}/location

Меняет локацию существующего заказа. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "location": "ams",
  "confirm": true
}
```

Используйте код локации из `GET /api/locations`. Доступность, ограничения заказа и стоимость проверяются по правилам личного кабинета.

Если требуется оплата:

```json
{
  "type": true,
  "data": {
    "order_id": 10001,
    "status": "payment_required",
    "payment_url": "https://pay.example.test/payment/example"
  }
}
```

Если доплата не требуется, запрос возвращает HTTP `202` и `status=accepted`. После завершения обновите информацию о заказе и его VPS.

### POST /api/orders/{id}/processor

Меняет тип процессора существующего заказа. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "processor": "amd",
  "confirm": true
}
```

`processor` принимает `intel` или `amd`. Передавайте нужный тип процессора. Если он уже установлен, метод возвращает HTTP `200`, `status=unchanged` и текущее значение `processor`.

При необходимости оплаты возвращаются `status=payment_required` и `payment_url`. Если доплата не требуется, запрос возвращает HTTP `202` и `status=accepted`. Доступность и ограничения проверяются по правилам кабинета.

### POST /api/orders/{id}/options

Добавляет выделенный IP, NVMe или резервное копирование к существующему заказу. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

| Параметр | Тип | Описание |
|---|---|---|
| `static_ip` | boolean | Докупить выделенный IP; по умолчанию `false` |
| `nvme` | boolean | Докупить NVMe; по умолчанию `false` |
| `backup` | boolean | Докупить резервное копирование; по умолчанию `false` |
| `confirm` | boolean | Должен быть `true` |

```json
{
  "static_ip": true,
  "nvme": false,
  "backup": true,
  "confirm": true
}
```

Передайте хотя бы одну опцию со значением `true`. Метод добавляет опции; `false` не отключает уже подключённую услугу. Цена рассчитывается кабинетом для заказа и оставшегося срока. Ответ содержит `status=payment_required` и `payment_url`.

Возвращает VPS текущего аккаунта.

Query-параметры:

| Параметр | По умолчанию | Ограничение |
|---|---:|---:|


### GET /api/vps/availability

Проверяет доступность конфигурации перед созданием VPS.

Query-параметры:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `tariff_id` | — | Обязательный ID тарифа |
| `location` | `msk` | Код локации из `GET /api/locations` |
| `processor` | `intel` | `intel` или `amd` |
| `system` | `ubuntu_24` | Код ОС из `GET /api/systems` |
| `count` | `1` | От `1` до `10` |
| `static_ip` | `0` | `0` или `1` |
| `nvme` | `0` | `0` или `1` |

```json
{
  "type": true,
  "data": {
    "available": 2,
    "max_available": 3,
    "requested": 2,
    "can_create": true,
    "reason": null
  }
}
```

Метод использует проверку доступности кабинета. Результат может кэшироваться до 30 секунд и не резервирует ресурсы. Перед покупкой доступность проверяется повторно. Неизвестная или неактивная пара локации и процессора возвращает `configuration_unavailable`.

### POST /api/vps/create

Создаёт VPS и списывает стоимость с баланса. Требуются IP whitelist и `confirm=true`.

| Параметр | Тип | Описание |
|---|---|---|
| `period` | integer | Срок аренды в днях |
| `tariff_id` | integer | ID из `GET /api/tariffs` |
| `location` | string | Код из `GET /api/locations` |
| `processor` | string | Тип из `GET /api/locations` |
| `system` | string | Код из `GET /api/systems` |
| `skip_desktop_link` | boolean | Не создавать ярлык OneDash «Services and Contacts» (`links.onedash.net`) на общем рабочем столе Windows. Необязательный; по умолчанию `false`, для Linux не влияет |
| `count` | integer | Количество VPS, от `1` до `10` |
| `additional_options.static_ip` | boolean | Выделенный IP |
| `additional_options.nvme` | boolean | NVMe-диск |
| `additional_options.backup` | boolean | Резервное копирование |
| `confirm` | boolean | Должен быть `true` |

```json
{
  "period": 30,
  "tariff_id": 5,
  "location": "msk",
  "processor": "intel",
  "system": "windows_10_ru",
  "skip_desktop_link": true,
  "count": 1,
  "additional_options": {
    "static_ip": true,
    "nvme": false,
    "backup": true
  },
  "confirm": true
}
```

В этом примере ярлык OneDash со ссылкой на `links.onedash.net` не будет создан на рабочем столе Windows. Передавайте `skip_desktop_link` как JSON boolean (`true` или `false`), а не как строку. Если параметр отсутствует или равен `false`, ярлык создаётся как обычно.

```json
{
  "type": true,
  "order_id": 10001
}
```

Создание выполняется асинхронно. Ожидайте появления готовой VPS в `GET /api/vps` и проверяйте `credentials_ready`.

Если заказ уже оплачен, но запуск создания не подтверждён, ответ возвращается с HTTP-кодом `202`, тем же `order_id` и полем `"processing": true`. Не повторяйте `POST /api/vps/create`: проверяйте этот заказ через `POST /api/orders/info` и список VPS. Повторный запрос создания оформляет новый заказ.

### POST /api/vps/clone

Клонирует исходную VPS на 1–5 целевых VPS. Требуются IP whitelist и `confirm=true`.

```json
{
  "source_vps_id": 20001,
  "target_vpses": [20002, 20003],
  "confirm": true
}
```

```json
{
  "type": true
}
```

Целевые VPS должны принадлежать тому же аккаунту и быть пригодны для операции. До завершения клонирования не запускайте на них другие действия.

### POST /api/vps/{id}/credentials

Возвращает данные подключения к VPS. Требуется IP whitelist. Тело запроса может быть пустым JSON-объектом.

```json
{}
```

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "protocol": "ssh",
    "connection": {"host": "203.0.113.20", "port": 22},
    "login": "root",
    "password": "EXAMPLE_PASSWORD"
  }
}
```

Ответ содержит секретные данные. Не кэшируйте его и не сохраняйте пароль в логах.

### POST /api/vps/{id}/rename

Меняет отображаемое имя VPS. Максимальная длина — 40 символов. Пустое имя сбрасывает пользовательское название.

```json
{
  "name": "Production VPS"
}
```

```json
{
  "type": true,
  "data": {"vps_id": 20001, "name": "Production VPS"}
}
```

### GET /api/vps/{id}/power

Возвращает состояние питания и последней команды.

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "power_state": "running",
    "power_action": "reboot",
    "power_action_status": "done",
    "busy": false,
    "stale": false
  }
}
```

### POST /api/vps/{id}/power

Отправляет команду питания.

Допустимые значения `action`: `start`, `reboot`, `shutdown`.

```json
{
  "action": "reboot"
}
```

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "action": "reboot",
    "power_action_status": "queued"
  }
}
```

Проверяйте завершение через `GET /api/vps/{id}/power`.

### GET /api/vps/{id}/ptr

Возвращает текущую PTR-запись и состояние последнего запроса.

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "ip": "203.0.113.20",
    "current_ptr": "host.example.com.",
    "last_request": null
  }
}
```

### POST /api/vps/{id}/ptr

Устанавливает или удаляет PTR-запись.

Установка:

```json
{
  "ptr": "host.example.com"
}
```

Удаление:

```json
{
  "delete": 1
}
```

Успешный запрос возвращает HTTP `202`. Проверяйте результат через `GET /api/vps/{id}/ptr`.

### POST /api/vps/{id}/password

Ставит смену пароля в очередь. Требуется IP whitelist.

Требования к паролю:

- от 13 до 20 символов;
- минимум одна цифра;
- минимум одна заглавная латинская буква;
- допустимы латинские буквы, цифры и символы `!@#%^*_+=.,:?-`.

```json
{
  "password": "ExampleSecure9!"
}
```

Успешный запрос возвращает HTTP `202`:

```json
{
  "type": true,
  "data": {
    "request_id": 30001,
    "vps_id": 20001,
    "status": "queued"
  }
}
```

### GET /api/vps/{id}/password/{request_id}

Возвращает состояние смены пароля. Требуется IP whitelist.

Возможные значения `status`: `queued`, `processing`, `success`, `failed`.

```json
{
  "type": true,
  "data": {
    "request_id": 30001,
    "vps_id": 20001,
    "status": "success",
    "finished": true,
    "successful": true,
    "created_at": 1893456000
  }
}
```

### GET /api/vps/{id}/ips

Возвращает варианты смены IP для VPS текущего аккаунта.

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "choices": [
      {"value": "203.0.113.21", "ip": "203.0.113.21"}
    ],
    "requires_recreate": false,
    "first_ip_change_free_available": false,
    "price": "100",
    "currency": "RUB"
  }
}
```

Для выделенного IP `value` содержит адрес. Для общего IP `value` содержит ID целевой ноды строкой, `ip` — отображаемый адрес, а `requires_recreate=true` предупреждает о пересоздании VPS с потерей данных. В запрос смены передавайте именно `value`.

Список и цена не резервируются. Доступность адреса и право на бесплатную смену проверяются повторно при оформлении.

### POST /api/vps/{id}/ip

Оформляет смену IP существующего VPS. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "new_ip": "203.0.113.21",
  "confirm": true
}
```

`new_ip` — строка из поля `value` метода `GET /api/vps/{id}/ips`. Если `requires_recreate=true`, дополнительно передайте `"allow_data_loss": true`. Без этого подтверждения возвращается `data_loss_confirmation_required`.

Платная смена возвращает `status=payment_required` и `payment_url`. Бесплатная смена может вернуть `status=completed` или HTTP `202` со `status=accepted`. После завершения обновите данные подключения к VPS.

### GET /api/vps/{id}/snapshots

Возвращает список снимков VPS и состояние связанных операций.

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "items": [],
    "count": 0,
    "limit": 3
  }
}
```

### POST /api/vps/{id}/snapshots

Создаёт снимок VPS. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

| Параметр | Тип | Описание |
|---|---|---|
| `title` | string | Название до 120 символов; по умолчанию пустая строка |
| `description` | string | Описание до 500 символов; по умолчанию пустая строка |
| `include_ram` | boolean | Сохранять состояние памяти; по умолчанию `false` |
| `confirm` | boolean | Должен быть `true` |

```json
{
  "title": "Перед обновлением",
  "description": "",
  "include_ram": false,
  "confirm": true
}
```

Успешный запрос возвращает HTTP `202`:

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "snapshot_id": 30001,
    "status": "accepted"
  }
}
```

Состояние снимка проверяйте через `GET /api/vps/{id}/snapshots`. Ограничения на создание и параллельные операции совпадают с личным кабинетом.

### POST /api/vps/{id}/snapshots/{snapshot_id}/rollback

Восстанавливает VPS из его снимка. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "confirm": true
}
```

Изменения после создания снимка будут потеряны. Успешный запрос возвращает HTTP `202`, `vps_id`, `snapshot_id` и `status=accepted`. Проверяйте состояние VPS и снимка до следующей операции.

### POST /api/vps/{id}/snapshots/{snapshot_id}/delete

Удаляет снимок VPS. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "confirm": true
}
```

Успешный запрос возвращает HTTP `202`, `vps_id`, `snapshot_id` и `status=accepted`. Удаление снимка необратимо.

### GET /api/vps/{id}/backups

Возвращает список резервных копий. Метод доступен только для VPS с подключённой опцией резервного копирования.

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "enabled": true,
    "items": [],
    "count": 0
  }
}
```

### POST /api/vps/{id}/backups/sync

Синхронизирует список резервных копий VPS с сервером хранения. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "confirm": true
}
```

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "status": "completed",
    "count": 2
  }
}
```

Синхронизация обновляет список существующих копий и не создаёт новую резервную копию. После неё запросите `GET /api/vps/{id}/backups`.

### POST /api/vps/{id}/backups/{backup_id}/restore

Восстанавливает VPS из его резервной копии. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "confirm": true
}
```

Текущие данные VPS будут заменены данными копии. Успешный запрос возвращает HTTP `202`, `vps_id`, `backup_id` и `status=accepted`. До завершения проверяйте состояние VPS и резервной копии.

### POST /api/vps/{id}/backups/{backup_id}/delete

Удаляет резервную копию VPS. Требуются IP whitelist, `confirm=true` и `Idempotency-Key`.

```json
{
  "confirm": true
}
```

Успешный запрос возвращает HTTP `202`, `vps_id`, `backup_id` и `status=accepted`. Удаление резервной копии необратимо.

### POST /api/vps/{id}/reinstall

Запускает переустановку ОС. Все данные VPS будут удалены. Требуются IP whitelist и `confirm=true`.

```json
{
  "system": "ubuntu_24",
  "confirm": true
}
```

Успешный запрос возвращает HTTP `202`:

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "old_system": "ubuntu_22",
    "new_system": "ubuntu_24",
    "status": "reinstalling"
  }
}
```

После завершения обновите список VPS и заново получите реквизиты доступа. Во время переустановки идентификатор VPS в списке может измениться.

### GET /api/vps/{id}/delete-info

Предварительно рассчитывает возврат перед удалением. Метод ничего не удаляет.

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "order_id": 10001,
    "refund_amount": 25,
    "currency": "ru",
    "days_left": 15,
    "early_delete": false,
    "early_fee": 0,
    "note": null
  }
}
```

Перед удалением всегда показывайте пользователю актуальные значения из этого ответа.

### POST /api/vps/{id}/delete

Безвозвратно удаляет VPS и выполняет предусмотренный расчёт возврата. Требуются IP whitelist и `confirm=true`.

```json
{
  "confirm": true
}
```

```json
{
  "type": true,
  "data": {
    "vps_id": 20001,
    "refund_amount": 25,
    "refund_amount_text": "25 ₽",
    "early_delete": false,
    "early_fee": 0,
    "status": "deleting"
  }
}
```

Операция необратима. Не повторяйте запрос после успешного ответа.

## Рекомендации для интеграции

- Храните API-ключ в менеджере секретов или переменной окружения.
- Ограничьте ключ IP whitelist и выдайте отдельный ключ каждой интеграции.
- Устанавливайте таймауты соединения и чтения.
- При `429` соблюдайте `Retry-After`.
- Для асинхронных операций используйте опрос с интервалом, а не частые запросы.
- Перед списанием средств или удалением показывайте пользователю параметры операции.
- После переустановки, клонирования и создания обновляйте список VPS.
- Не передавайте ключи, пароли и платёжные ссылки третьим лицам.
